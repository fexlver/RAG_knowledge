# 2026-08-23 · 精确事实行加分：evidence_hit@5 0.53 -> 0.72

> 对应提交：`feat: 检索精确事实行加分（实体锚定），evidence_hit@5 0.53->0.72`
> 输入：Golden Set v0 发现"数字题的表格分片排在第 6 名开外"；本次调优用同一评测集验证收益。

## 做了什么

按 Golden Set 暴露的靶点实施检索调优，历经四轮迭代，全部在同一评测集上验证：

1. **精确事实行加分**：问题关键词命中 markdown 表格行标签格的候选，rerank 后加分；
2. **实体锚定**：关键词需命中来源文件名（公司名天然在文件名里），否则跨公司标签行全被误抬；
3. **候选回填**：表格分片不含公司名，词法检索里与所有公司同名行并列（排 38+）、语义 50+，RRF 融合后掉出候选池——从各路召回的完整列表里把通过守门且标签命中的分片捞回重排队列（按命中数排序取前 8）；
4. **特指词过滤**：jieba 把"营业收入"拆成两个 2 字词（营收题颗粒无收），而孤立 2 字泛词（风险/利润）又会误伤章节题——用"≥3 字单词 + 相邻分词拼接复合词"两头兼顾。

附带修复：引用构建按（页码,章节）去重会把同页表格兄弟分片切掉一半，改为按 chunk_id 去重。
召回深度调整：LEXICAL_TOP_K 15→60（SQLite 毫秒级，回填需要深列表）、FUSION_TOP_K 12→20；DENSE_TOP_K 试过 30 后回收（改变融合池构成反而引入波动，且目标分片语义排名 50+ 用不上）。

## 遇到的问题与该怎么办

| 问题 | 根因 | 应对（通用方法） |
| --- | --- | --- |
| 无锚定版把别家公司的同标签行全部抬进 top-5 | 加分只看"标签行匹配"，不知道块属于哪家公司 | **加分/加权类后处理必须锚定实体**：用块的元数据（文件名含公司名）做守门条件。方法：给排序信号加规则时，先问"这个规则会不会跨实体误伤"，用元数据字段守门 |
| rerank 直接砍到 top-5，加分来不及 | 加分发生在 rerank 之后，但候选已被裁剪 | 后处理加分要求排序阶段保留候选池（top_k + pool），加完分再裁剪 |
| 测试夹具文件名不含公司名导致单测挂 | 锚定规则正确拒绝了无实体来源的块 | 测试夹具要与真实数据形状一致（文件名含公司名），恰好反向验证了锚定逻辑生效 |
