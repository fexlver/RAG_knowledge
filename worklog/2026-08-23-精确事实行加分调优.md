# 2026-08-23 · 精确事实行加分：evidence_hit@5 0.53 -> 0.72

> 对应提交：`feat: 检索精确事实行加分（实体锚定），evidence_hit@5 0.53->0.72`
> 输入：Golden Set v0 发现"数字题的表格分片排在第 6 名开外"；本次调优用同一评测集验证收益。

## 做了什么

按 Golden Set 暴露的靶点实施第一个检索调优：**精确事实行加分**。问题关键词命中 markdown 表格行首列（标签格）的候选块，在 rerank 后获得分数加成，让"营业收入那一行"所在的分片战胜同页兄弟分片进入 top-5。

## 用了什么技术

- **加分规则**：`fact_boost.py` 用 jieba 分词提取问题关键词（过滤虚词/单字/纯数字），块内容里表格行标签格（`| 营业收入 |` 的第一格，去空格归一化后）包含关键词即加分（每命中一词 +0.15，上限 0.45）。正文段落没有表格行结构，天然不加分——加分只改变"表格行分片 vs 其他内容"的相对顺序。
- **实体锚定（踩坑后的关键修正）**：第一版无锚定，把所有公司的净利润行都抬进了"金正大"问题的 top-5，doc_hit 从 1.0 跌到 0.97。修正：问题关键词还需命中块的**来源文件名**（公司名天然在年报文件名里）才加分，跨文档标签行不再加分。
- **候选池扩容**：rerank 从"直接砍到 5"改为"先取 5+10 个候选，加分重排后再裁剪"——否则目标分片在加分前就已被裁掉。
- 配置化：`FACT_BOOST_POOL`（默认 10）、`FACT_BOOST_WEIGHT`（默认 0.15）。

## 解决了什么问题（效果怎么样）

同一 Golden Set（9 文档 34 题）前后对比：

| 指标 | 调优前 | **调优后** |
| --- | --- | --- |
| evidence_hit@5（top-5 含期望事实） | 0.53 | **0.72**（+19pp） |
| doc_hit@5（找对公司） | 1.00 | **1.00**（无回退） |
| MRR | 0.86 | **0.91** |
| 答案层 keyword_hit | 0.63 | **0.81** |
| 拒答准确性 | 0.65 | **0.74** |
| 检索延迟 | 0.48s | 0.45s/题（无额外开销） |

端到端也改善：答案层关键词命中从 63% 升到 81%，被动拒答（检索拿不到精确数字导致"无法确认"）减少。

测试：fact_boost 单元测试 7 个（含跨文档不加分、docling 断空格容差、虚词过滤），全量 52 个后端测试通过。

## 遇到的问题与该怎么办

| 问题 | 根因 | 应对（通用方法） |
| --- | --- | --- |
| 无锚定版把别家公司的同标签行全部抬进 top-5 | 加分只看"标签行匹配"，不知道块属于哪家公司 | **加分/加权类后处理必须锚定实体**：用块的元数据（文件名含公司名）做守门条件。方法：给排序信号加规则时，先问"这个规则会不会跨实体误伤"，用元数据字段守门 |
| rerank 直接砍到 top-5，加分来不及 | 加分发生在 rerank 之后，但候选已被裁剪 | 后处理加分要求排序阶段保留候选池（top_k + pool），加完分再裁剪 |
| 测试夹具文件名不含公司名导致单测挂 | 锚定规则正确拒绝了无实体来源的块 | 测试夹具要与真实数据形状一致（文件名含公司名），恰好反向验证了锚定逻辑生效 |
