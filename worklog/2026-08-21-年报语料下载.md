# 2026-08-21 · 年报语料下载（100 份种子）

> 产出：`scripts/download_annual_reports.py`、`corpus/raw/`（101 个 PDF，460MB）、`corpus/manifest.csv`

## 做了什么

解决"没有大规模数据支撑系统"的问题：确定语料策略，写批量下载脚本，从巨潮资讯网拉取 **100 份 2023 年 A 股年报**，作为企业升级 Phase 0 的解析样张和后续建库种子。

## 用了什么技术

- **cninfo（巨潮资讯网）公告查询 API**：`POST http://www.cninfo.com.cn/new/hisAnnouncement/query`，参数 `column=szse|sse`（交易所）、`plate=sz|sh`、`category=category_ndbg_szsh`（年报）、`trade=<行业>`、`seDate`（日期区间）、分页 `pageNum/pageSize`；PDF 下载地址是 `http://static.cninfo.com.cn/{adjunctUrl}`；
- **行业分散采样**：16 个申万行业来源（深市+沪市），每个行业取 6-7 家公司，避免语料同质化（医药制造、电子、货币金融、保险、计算机通信等）；
- **标题过滤规则** `pick_title()`：排除"摘要/英文/取消/更新/补充/更正/问询/回复/披露/提示性"公告，"修订"版作备选优先级 1，保证拿到的是正式完整年报；
- **工程可靠性**：全局 `secCode` 去重、1.2 秒限速、sha256 写入 `corpus/manifest.csv`（含 sec_code/sec_name/industry/year/title/announcement_id/published_at/size_kb/status）、断点续跑。

## 解决了什么问题

- **语料选型**：数据在三套系统里扮演三种角色，不能混为一谈：
  1. **解析质量评估**：需要真实、复杂、免费公开的文档 -> 年报（数字原生 PDF、双层表头财务表、跨页大表、图文混排，难度天花板高）；
  2. **Golden Set**：50-200 对人工标注 QA，用于检索/回答评测（后续建）；
  3. **规模压测**：用模板合成（改数字/改公司名/复制变体）造 1万-10万份，测试索引吞吐和删除一致性（后续建）。
- **领域灵活性**：用户明确说不一定做食品安全，其他领域都行 -> 年报是完美的替代领域：公开免费、量足够大（每年几千份）、结构复杂度远超食品安全标准文档。

## 效果怎么样

- **100/100 全部下载成功**，460MB，15 个行业 × 6-7 家公司；
- 文件名 `000010_美丽生态_2023.pdf`（代码_公司_年份），manifest 带 sha256 和元数据，可直接进后续入库流水线；
- 这批语料当天就支撑了 Docling spike（3 份样本解析全部成功）。

## 遇到的问题与该怎么办

| 问题 | 应对 |
| --- | --- |
| 下载列表里混着摘要版、英文版、更正公告 | 标题关键词过滤 + 全局代码去重。**方法：爬公开数据源时，先人工看 20 条原始结果的脏数据模式，再写过滤规则** |
| Git Bash 里路径结尾的反斜杠把闭合引号转义了（`...corpus\raw\"`），命令莫名报错 | Windows 下 shell 命令统一用正斜杠路径。**方法：引号错乱先查反斜杠** |
| 磁盘空间顾虑 | 实测 100 份仅 460MB（年均 4.6MB），10 万份量级 ≈ 460GB，在 2TB NVMe 预算内；合成压测数据可按需造，不用全存真文档 |

## 复习要点

- 公开金融数据源：巨潮（公告原文）、上交所/深交所官网；年报 API 的 `category_ndbg_szsh` 是关键参数；
- 语料设计的三角色模型（质量样本 / Golden Set / 压测合成）适用于任何 RAG 项目冷启动；
- 下载脚本的三件套：限速、去重、manifest（哈希+元数据），缺一个后期都要返工。
