# 企业级私有化多模态 RAG 工作台升级方案（修订版）

> 基于 Codex 初版方案的评审修订。修订核心：砍掉 OpenSearch、解析验证提前为 Phase 0、
> 增加建库吞吐预算、写死 ACL 预过滤与删除一致性机制、补评测体系与语义缓存。
> 标注【修订】的条目为相对初版的变更，未标注的条目维持原方案。

## 总结

在现有仓库上分期升级，目标是"部门级内网试点"：1–10 万份资料、20–50 名在线用户、完全离线、本地账号与角色权限、网页上传加内网目录增量同步。

首期重点是可信文档问答：复杂文档结构解析、精准证据引用、权限过滤、异步可恢复建库。多模态以"OCR 主链路 + VLM 按需增强"实现；音频预留插件接口，放入第二期。

Docling 作为统一文档转换层，输出 Markdown、版面元素和表格结构；中文扫描件 OCR 用 RapidOCR（PaddleOCR 模型的 ONNX 封装，Docling 原生支持该引擎），不单独编写 PaddleOCR 适配器。【修订】Phase 0 将用真实样张对比评测 Docling + RapidOCR 与 PaddleOCR-VL（0.9B 文档解析专用 VLM，8GB 显存可跑）后定主链路。Markdown 是检索投影，不是唯一原始事实；原文件、结构化版面 JSON 与坐标定位共同构成可追溯数据。

## 核心架构

- 保留 FastAPI 与 React 工作台，拆分为网关、文档解析、异步入库、检索、模型推理五类服务。
- SQLite 升级为 PostgreSQL：保存用户、角色、文档版本、ACL、元数据、任务状态、审计日志与检索策略。
- MinIO 保存原文件、页面渲染图、图片裁剪、结构化 Markdown/JSON 和音频片段；Milvus 保存文本与图像向量；**不引入 OpenSearch**。【修订】关键词检索由 Milvus 2.5+ 内置 BM25 全文检索承担（稀疏向量 + 内置 jieba 中文分析器），元数据过滤走 PostgreSQL。理由：单机 64GB 内存预算下省掉一个 4–6GB 的常驻服务与离线插件运维（IK 分词器）；原子索引切换少协调一个索引；部门级 10 万文档规模完全够用。将来若需要分面搜索 / 聚合面板再评估加回。
- Redis + Celery 承担异步任务、重试、进度、限流和 GPU 队列。任务按 CPU 解析、Embedding、VLM 增强分队列执行。
- 单张 RTX 5060 8GB GPU。【修订】需写明 Blackwell（sm_120）约束：CUDA 12.8+，vLLM 须用新版；保守选项是 llama.cpp / Ollama。显存预算：OCR、Embedding 与 Rerank 默认走 CPU/ONNX；本地量化生成模型（Qwen3-4B 或 Qwen2.5-7B int4）允许 2–3 路并发；VLM（Qwen2.5-VL-7B 量化）单独运行即占满整卡，**与生成任务互斥共用 GPU 队列不是优化项，是硬约束**，低优先级、不全量逐页运行。
- 【修订】增加语义缓存层：试点期 20–50 人共用一张 8GB 卡，重复问题命中率高。命中条件 = 问题向量相似 + 权限维度一致（cache key 必须包含用户可见的 ACL 范围，否则越权泄露），可显著缓解 GPU 排队。

## 文档理解、切块与建库

- 建立统一的 `DocumentVersion -> Section -> Element -> EvidenceUnit` 数据模型。
  - `Element` 区分标题、段落、列表、表格、图片、页眉页脚、音频转写片段。
  - 每个单元保存页码、章节路径、字符/行范围、PDF 归一化坐标、Excel Sheet/单元格范围、图片裁剪坐标或音频时间戳。
- 解析链路采用"版面结构优先、语义边界辅助"：
  - 标题、列表、表格、图片不被普通字符切块打断。
  - 段落只在同一章节内按语义连续性合并，默认目标 350–600 Token，并注入标题层级作为上下文。
  - 表格保留标题、表头与命中行；过长表按行组切分，避免只召回一个脱离表头的单元格。
  - 图片保存原图/裁剪图、OCR 文本、图注与按需 VLM 描述；音频第二期转为带时间戳的 ASR 片段。
  - 【修订】图片处理路由规则写明：纯文字扫描件走 OCR；含图表、流程图、公章标注的页标记为"待增强"，按需触发 VLM（OCR 只能转录文字，拿不到图表趋势与流程逻辑）。
  - 【修订】首期"生成模型理解多模态"的实现方式是投影：图片/表格通过 VLM 描述与 OCR 文本转成文本证据喂给纯文本生成模型，prompt 侧不用改；图直接进生成模型 context 留待第二期换多模态生成模型。
- 元数据覆盖来源路径、文件名、标题、文种、发布/生效日期、版本、哈希、上传人、部门、标签、有效状态、权限 ACL、解析器版本、Embedding 版本和索引版本。
- 入库任务具备幂等、断点续跑、批量 Embedding、动态批大小、失败重试与可观测进度；同内容哈希去重，不同版本建立独立 `DocumentVersion`。
- 索引构建完成前不切换线上版本；向量、关键词和元数据索引全部成功后，原子切换为当前可检索版本。
- 【修订】**建库吞吐预算**（10 万份 × 平均 30 页 ≈ 300 万页）：

  | 环节 | 单页成本（CPU 估算） | 全量估算（单进程） | 加速手段 |
  | --- | --- | --- | --- |
  | 数字原生 PDF 解析（免 OCR） | 0.1–0.5 s | 4–17 天 | 多 worker 并行 |
  | 扫描件 OCR（Docling 版面 + RapidOCR） | 1–3 s | 35–104 天 | 8–16 worker 并行、夜间批处理窗口 |
  | Embedding（bge-m3 ONNX int8） | 约 200–500 chunk/s | 500 万 chunk ≈ 3–7 小时 | 批量动态批 |
  | VLM 增强 | 按需 | 不做全量 | 仅"待增强"页、低优先级队列 |

  结论：**渐进式索引是硬要求**——文本索引先上线可检索，OCR 修正与 VLM 增强异步补充，不允许最慢环节阻塞索引可用；Milvus 写入统一走 bulk insert；数字原生与扫描件在任务入队时即分流。

## 混合检索与可信回答

- 将现有固定的 Dense/关键词/RRF/重排插件配置升级为集合级 `RetrievalPolicy`：
  - 启用路由、候选数、过滤字段、融合权重、Rerank 模型和阈值均可配置。
  - 新路由可注册为文本向量、关键词/BM25、标题与标准号精确匹配、元数据筛选、表格单元格、图文跨模态、音频转写和后续图谱检索。
  - 【修订】溯源上下文窗口大小也做成 `RetrievalPolicy` 可配参数，不同文档类型默认值不同（法规文本窗口小，技术规格书窗口大）。
- 权限、部门、密级、有效状态、日期和版本在所有召回前执行过滤；绝不先召回后过滤。
- 【修订】**ACL 预过滤的落地机制**（否则"召回前过滤"无法执行）：
  - 部门、密级等 ACL 字段**冗余存为 Milvus 标量字段**，查询时按用户角色直接生成 filter 表达式；
  - 10 万文档不能每次把 doc_id 白名单塞进查询表达式（表达式过长）；
  - ACL 变更触发定向标量更新任务，同步 Milvus 冗余字段与 PostgreSQL 权威记录。
- 【修订】**删除与权限收紧的一致性**：PG 删除记录后 Milvus 仍可能召回。引入 tombstone（软删除标记）+ 异步索引清理任务；权限收紧等同于对受影响文档执行 ACL 标量更新。验收测试必须包含"删除后立即检索不可见"。
- 文本向量、关键词（Milvus BM25）、标题/标准号精确匹配与元数据筛选用加权 RRF 融合，再由文本 Rerank（CPU/ONNX）或仅对 Top-N 的 VLM 做多模态重排；Milvus 原生支持多向量、稠密/稀疏组合检索。
- 回答接口返回结构化 `EvidenceRef`，包含文档版本、证据单元、模态、各路分数、定位器和预览范围；生成模型只能基于已授权证据回答。

## 溯源与前端交互

- 不在回答中返回整份文档，仅返回命中的 `EvidenceUnit` 与最小上下文窗口。
  - 段落：命中段落、父标题和相邻 1–2 个语义块。
  - 表格：表名、表头、命中行及上下各 2 行。
  - PDF：命中页与坐标高亮；点击后按需加载原文件页。
  - 图片：显示原图裁剪、OCR 文本、VLM 描述和来源页。
  - 音频：播放器跳转到命中时间段，并显示转写上下文。
- 新增 `GET /api/evidence/{id}/context` 与受权限保护的原文预览接口；前端右侧预览区按模态渲染 PDF、Markdown、Excel、图片和音频。
- 知识库页展示文件夹同步状态、文档版本链、解析质量、OCR/VLM 状态、任务日志、失败重试和索引版本。
- 设置页展示检索策略图、路由开关、候选数与融合权重，但 ACL、模型版本和系统安全配置仅允许管理员修改。
- 【修订】文件夹同步机制写明：**周期扫描 + mtime/size 变化检测 + 变化后内容哈希复核**，不使用 filesystem watch（离线内网 SMB/NAS 共享上 inotify 类机制不可靠）。

## 权限、审计与部署

- 本地账号采用 `admin / curator / viewer` 三类角色，密码使用 Argon2 哈希；文档按部门、角色、密级配置 ACL。
- 审计上传、版本切换、删除、同步、问答、证据预览和导出操作；审计记录关联用户、文档版本、任务和请求 ID。
- 使用 Docker Compose 打包单机内网试点：FastAPI、React 静态站点、PostgreSQL、MinIO、Redis、Celery、Milvus（含 BM25）、解析服务和本地模型服务。不需要 Kubernetes。【修订】服务清单较初版少一个 OpenSearch，内存预算同步下调。
- 所有容器镜像与模型权重支持离线导入；定期备份 PostgreSQL 与 MinIO，Milvus 索引允许由原始制品重新构建（bulk insert 快速重建）。
- 增加 Prometheus 指标与结构化日志：解析耗时、OCR 失败率、队列积压、GPU 利用、检索各路命中、Rerank 耗时、引用点击率、任务重试率和语义缓存命中率。【修订】缓存命中率纳入监控

## 评测体系【修订：新增章节】

"可信问答"是首期企业价值主张，必须可量化，否则无法回答"换了解析器/切块策略后质量变好还是变差"。现有 `eval/dataset.jsonl` 仅 2 条样例，需扩充。

- **Golden Set**：50–200 条真实问答对，覆盖事实型、版本比较型、表格数值型、拒答型（知识库不存在）四类；每条标注期望命中文档与证据单元。
- **核心指标**：
  - 解析质量：标题识别正确率、表格结构完整率、坐标定位准确率（Phase 0 用 20–50 份真实样张人工标注）；
  - 检索质量：召回率@k、引用命中精度/召回；
  - 可信度：拒答正确率（该拒的拒了）、误拒率（不该拒的拒了）；
  - 端到端：回答忠实度（结论是否被证据支撑）。
- **回归机制**：每期验收挂评测指标；解析器、切块策略、RetrievalPolicy 变更必须跑回归，指标不回退才可合并。

## 实施顺序与验收【修订：插入 Phase 0】

0. **Phase 0（1–2 周）解析质量 spike + Golden Set 建设**：在**现有 SQLite 栈**上直接接入 Docling + RapidOCR，另测 PaddleOCR-VL 对比；用 20–50 份真实样张（含扫描件、复杂表格、图文混排）量化解析质量。理由：解析质量是全系统最高技术风险、验证成本最低，其结论决定 Element 模型字段与切块策略；避免先花数周迁移基础设施后发现解析不达标要改数据模型。
1. 基础设施与迁移：引入 PostgreSQL、MinIO、Redis/Celery，迁移现有文档、版本、会话和检索配置；保留旧 SQLite 数据导入工具。
2. 可信文档链路：按 Phase 0 结论定稿结构化元素与语义切块，落地元数据、异步任务、渐进式索引、文件夹同步、原子索引版本切换与删除一致性。
3. 企业检索：SQLite FTS 替换为 Milvus BM25，接入 ACL 冗余字段预过滤、可配置检索策略、加权融合，评测集挂验收。
4. 多模态增强：图片/图表/复杂表格的 VLM 描述与跨模态检索（文本投影方式）；音频 ASR 与时间戳检索作为第二期插件。
5. 前端与运维：多模态溯源预览、任务监控、版本管理、审计页、语义缓存、离线部署与备份恢复演练。

测试覆盖解析格式与坐标、表格表头完整性、扫描件 OCR 降级、VLM 队列隔离与 GPU 互斥、角色越权检索、删除后不可见、文件夹重复同步、任务中断恢复、索引版本原子切换、引用范围最小化、多模态预览、语义缓存的 ACL 隔离，以及 20–50 用户并发下的队列/限流行为。

## 默认假设

部署主机除 RTX 5060 8GB GPU 外具备 32GB 内存、1TB NVMe 存储；首期支持 PDF、Word、Excel、图片，音频仅保留标准化插件接口；在线用户可并发使用系统，但本地生成与 VLM 通过队列限制并发，避免 GPU 过载。
